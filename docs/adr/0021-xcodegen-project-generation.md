# ADR-0021 — `project.yml` is the source of truth; the `.xcodeproj` is generated

- **Status:** Accepted
- **Date:** 2026-06-25
- **Source:** `project.yml`, [BUILD.md](../BUILD.md), `.gitignore`
- **Related:** [ADR-0005](0005-swiftui-ios-macos.md)

## Context

A committed `.xcodeproj` is a large generated-looking file that conflicts on
almost every branch, records absolute paths and per-developer state, and makes
"what changed in the build config" nearly unreadable in review.

## Decision

The Xcode project is generated by **XcodeGen from `project.yml`**, which is the
source of truth. `TrackTheMoney.xcodeproj` is **gitignored** and regenerated with
`xcodegen generate`. It is never hand-edited — changes made in Xcode's UI are
lost on the next generation.

One multiplatform app target covers iPhone, iPad, and Mac; the `app/` SPM package
stays independently buildable for fast headless iteration.

## Consequences

- Build configuration diffs are readable YAML, and project-file merge conflicts
  disappear.
- Editing build settings means editing `project.yml` and regenerating — a real
  workflow change for anyone used to Xcode's inspector.
- Anything the project needs must be expressible in the spec. Declaring the
  backup UTType required an `info:` block generating a partial Info.plist, which
  merges with `GENERATE_INFOPLIST_FILE`
  ([ADR-0018](0018-backup-format-sqlite-snapshot.md)); the generated plist is
  gitignored for the same reason.
- CI and fresh clones must run `xcodegen generate` before building.
